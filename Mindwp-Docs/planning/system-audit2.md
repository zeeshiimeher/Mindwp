## 6. Functional Reorder Summary

This is the second-pass regrouping requested after the folder-by-folder table. It is not a second full duplicate table; it is the audit sorted into same-kind work buckets so similar files sit together.

### High Duplication Clusters

- Service route wrappers: nearly all files in src/domains/services/pages/*/index.tsx.
- Service renderers: most files in src/domains/services/renderers/*Renderer.tsx, especially builder-family renderers.
- Service content pages: many files in src/domains/services/data/*.ts reuse the same narrative frame with small changes.
- Script validators: scripts/validators/*.ts and *.mjs have repeated repo walking, inventory logic, and overlapping policy boundaries.
- Image-system storage: src/lib/image-system/debug/*, learning/*, queue/*, dedup/*, and data/*.json repeat persistence patterns.
- Dashboard/report contracts: scripts/lib/report-*.mjs, scripts/core/*report*, src/lib/dev/*report*, and src/lib/dashboard/client-dashboard.ts all touch report vocabulary.

### Recommended Functional Order

1. Docs and manifests
2. Env and logging
3. SEO and indexing
4. Graph and content-quality core
5. CTA, contact, page identity, related-content policy
6. Dashboard and reporting contracts
7. Script orchestrators and runners
8. Script analyzers and validators
9. Domain config and registries
10. Service content data
11. Service route entries
12. Service renderers
13. Unit, integration, system, visual, and domain tests
14. Image-system config and types
15. Image-system providers, scoring, learning, queue, storage
16. Image-system rendering, layouts, illustrations, diagrams

### Fastest Cleanup Targets

1. Unify duplicated report/status contracts across scripts and src/lib/dev.
2. Collapse repeated service route wrappers into a route-entry factory.
3. Consolidate builder-family service renderers and builder-family content pages.
4. Merge overlapping SEO/indexing validators into clearer ownership boundaries.
