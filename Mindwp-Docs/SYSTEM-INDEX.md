# SYSTEM INDEX — MindWP

> How the MindWP system operates.
> Read this first before any system work.

---

## SYSTEM LAYERS

MindWP is governed by 6 layers. Each has a single responsibility.

### 1. TRUTH LAYER

| Property | Value |
|----------|-------|
| File | `Mindwp-Docs/SYSTEM-TRUTH.md` |
| Updated by | Human only (manual) |
| Contains | Current system reality — architecture, graph, design system, components, rules |
| Does NOT contain | Problems, risks, plans, tasks, history |

SYSTEM-TRUTH is the master reference. All other layers derive from or validate against it.

### 2. STATE LAYER

| File | Purpose | Generated by |
|------|---------|-------------|
| `reports/system-state.json` | Validator results (machine-readable) | `generate-system-log.mjs` |
| `Mindwp-Docs/SYSTEM-LOG.md` | Validator results + system health (human-readable) | `generate-system-log.mjs` |
| `reports/system-drift.json` | Drift between SYSTEM-TRUTH and live code | `system-sync.mjs` |

All state files are auto-generated. Never edit manually.

### 3. DECISION LAYER

| Property | Value |
|----------|-------|
| File | `Mindwp-Docs/system/DECISION-STATE.md` |
| Generated by | `system-sync.mjs` |
| Contains | Active decisions only (Q1-Q6 + core rules) |
| Does NOT contain | History, timelines, rationale |

Overwritten on every sync run. No append. No history.

### 4. TASK LAYER

| Property | Value |
|----------|-------|
| File | `Mindwp-Docs/project-todo.md` |
| Updated by | Human or AI (during task planning) |
| Contains | Phased tasks (T-075+), priorities, statuses, expected outcomes |
| Phases | 3.1 Critical Fixes → 3.2 Design Compliance → 3.3 Graph Integrity → 3.4 Cleanup → 3.5 Hardening |

### 5. VALIDATION LAYER

| Property | Value |
|----------|-------|
| Location | `scripts/validation/` + `scripts/validate-*.cjs` + `scripts/validate-*.ts` |
| Orchestrator | `scripts/validate-all.mjs` (27 validators) |
| Log engine | `scripts/generate-system-log.mjs` (5 enforcement validators → state + log) |
| Purpose | Enforce rules from SYSTEM-TRUTH against live code |

### 6. SYNC LAYER

| Property | Value |
|----------|-------|
| File | `scripts/system-sync.mjs` |
| Purpose | Orchestrate all layers. Detect drift. Update state. |
| Runs | `generate-system-log.mjs` → extract truth signals → compare live code → write drift + decisions + health |
| Outputs | `system-drift.json`, `DECISION-STATE.md`, SYSTEM HEALTH in `SYSTEM-LOG.md` |

---

## WORKFLOW

### Per change / daily

```
1. Run sync
   node scripts/system-sync.mjs

2. Check outputs
   - reports/system-drift.json    → drift items
   - Mindwp-Docs/SYSTEM-LOG.md   → validator status + health

3. If drift exists
   → Fix code to match SYSTEM-TRUTH
   OR
   → Update SYSTEM-TRUTH to match code (manual only)

4. Execute tasks
   → Pick from project-todo.md (phase order)
   → Mark completed when done
```

### Health statuses

| Status | Condition |
|--------|-----------|
| CLEAN | 0 violations + 0 drift |
| WARNING | < 20 total issues |
| BROKEN | 20+ total issues |

## AI OPERATION RULES

### AI MUST

- Read SYSTEM-INDEX.md before any system work
- Follow layer separation — each file has one job
- Run `system-sync.mjs` after code changes
- Update `project-todo.md` to reflect completed work
- Use `system-state.json` and `system-drift.json` for current status

### AI MUST NOT

- Write problems, risks, or plans inside SYSTEM-TRUTH.md
- Manually edit auto-generated files (system-state.json, system-drift.json, DECISION-STATE.md, SYSTEM-LOG.md)
- Create duplicate decision sources
- Mix truth with tasks
- Auto-update SYSTEM-TRUTH.md without explicit human instruction
