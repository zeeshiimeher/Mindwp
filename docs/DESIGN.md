# DESIGN — MindWP

The visual authority. **This doc is the quality standard — not the existing pages.**

Read that twice. Every previous rebuild looked the same because the old docs said "use the current pages as the quality standard," so each AI faithfully cloned the same SaaS-editorial look. That instruction is dead. The reference pages (the Figma Make draft, the rebuilt Home, the Smart Website page) are **research into craft level**, not a template to reproduce. When DESIGN.md and an existing page disagree, DESIGN.md wins.

We are **designing in Figma first** (whole site), then building code later. So this doc is about visual direction, not CSS tokens.

## The genre: proof & work-led authority agency

MindWP looks like a confident, senior **studio that builds and runs websites** — warm, human, and grounded in visible work. It does **not** look like a SaaS product marketing site (Linear/Vercel/Stripe), and it does not look like a magazine.

The feeling: *a real builder who has shipped real sites since 2015 is showing you their work and telling you plainly what they'd do for you.* Premium, calm, credible, commercially serious — but with warmth and a human hand, not abstract product gloss.

## What changed, and why

The old DNA sold a philosophy with abstract product UI. The new genre sells a service with **real work and a clear offer.** Concretely:

| Old DNA (retired) | New genre |
| --- | --- |
| Dark/teal-glow "anchor" sections as the default rhythm | Light, warm, confident default; dark used rarely and only when earned |
| Faux dashboards, fake logs, fake SMS transcripts | Real build screenshots, device frames, honest diagrams, SVG illustration |
| "Example service site" mockups standing in for proof | Actual demonstration builds shown big |
| Monospace "data" microcopy (`MISSED`, `STALLED`, `jobs · 8`) | Plain human language |
| Every section a rounded-card grid | Varied silhouettes; each section earns its shape |
| Fixed template on every page | Page-specific composition |

## Hard bans (kills the old look)

These are not advisory. A design that uses them is wrong, regardless of polish:

- **No dark + teal/cyan-glow "anchor" sections as the recurring rhythm.** Dark is a rare punctuation (the five-system section, the final CTA may be dark), never the every-other-section beat.
- **No faux dashboards, fake admin UIs, fake logs, fake SMS/chat transcripts, fake CRM panels.**
- **No monospace "data" microcopy** used as decoration (`MISSED` / `WAITING` / `STALLED` / `jobs · 8` / `CONTROL SURFACE · LIVE` / `STEP 01 · …`).
- **No fake proof of any kind** — no invented ratings, review counts, star rows, phone numbers, testimonials, client names, metrics, rankings, or guarantees.
- **No "example service site" placeholder mockups pretending to be real businesses.** If a site is shown, it is a real demonstration build or anonymised real work.
- **No card-grid-everywhere.** Three-up rounded cards are allowed once or twice per page at most, not as the spine.
- **No "control surface," "operating system," or product-dashboard metaphors** for the five systems.

## In (the new toolkit)

- **Real work shown big.** Demonstration builds and anonymised client sites in clean, generous device/browser frames — the recurring hero motif of the site. Quality of the shown work *is* the design.
- **Human texture.** Founder/team/process presence (no stock handshake photos, no fake faces — real or tasteful illustration). The brand has a person behind it.
- **Concrete offer blocks.** What's included, how it works, what you keep, a quiet pricing/scope posture — shown plainly, not as feature tiles.
- **SVG illustration.** Custom, on-brand line/flat illustration is welcome to carry concepts (a handoff path, a local-area map, a "what changes over time" ladder) **instead of** faux-UI. Illustration over fake-dashboard, every time.
- **Honest diagrams.** Simple, legible diagrams of a real idea (the connected handling path, the five-system hub) — clearly illustrative, not pretending to be software.
- **Varied silhouettes.** Editorial splits, full-bleed work frames, statement bands, ladders, comparison columns, galleries — different shapes doing different jobs.

## "Editorial" means content discipline, not a visual style

When a section is called "editorial," it means **clear hierarchy** — a confident headline, a tight lead line, supporting copy — *not* a text-only magazine spread. Every "editorial" section still carries a **real artifact** on one side or behind it: a build screenshot, a device frame, a diagram, or an SVG illustration. 

**No section may render as a plain text block or an empty placeholder.** If a section has nothing concrete to show, it is not finished.

## Graphs and stats

Allowed **sparingly**, where a section genuinely needs one (e.g. a simple "what changes over time" visual). Never the default texture, never fake data, never the SaaS-sparkline-in-every-card pattern. Prefer an SVG illustration or a plain statement over a chart.

## Dark sections

Dark is a **punctuation mark**, not the rhythm. Reasonable dark moments: the five-system architecture section, the final CTA, maybe the hero. Three+ dark "anchors" on one page is the old DNA — don't. When dark is used, it's a deep confident base, not a glowing product-hero gradient.

## Five-system visual rule (protected)

Smart Website Systems is the **flagship/hub**; the other four are connected protections around it. **Never** five equal tiles, never a 2×3 grid, never a product-dashboard "control surface." Acceptable: a flagship row + four supporting cells, or a hub + four orbital positions **with a real connecting graphic** (not whitespace). Calm rows over glowing panels.

## Palette & type direction (for Figma)

- **Type:** keep the premium scale and spacing discipline from the reference pages — that craft level is the bar. Large confident display headings, comfortable measure, generous whitespace.
- **Palette:** warmer and more confident than the old cold navy + neon teal. Move toward a grounded, trustworthy base with a warmer accent and plenty of light/paper space. Decide the exact palette in Figma early and apply it consistently. The goal is "senior studio," not "tech startup."
- **Motion (later, in code):** calm and purposeful only. Not a design-phase concern.

## Per-section checklist

Before a section is "done":

1. Does it carry a **real artifact** (work screenshot / device / diagram / SVG) — not a placeholder?
2. Is its **silhouette different** from the sections above and below it?
3. Is it free of every **hard ban** (no faux dashboard, no monospace data, no dark-glow-default, no fake proof)?
4. Does it move the buyer along the conversion sequence (situation → slip → change → proof → next step)?
5. Would a real service-business owner or clinic manager find it **clear and credible** — not clever?

## Per-page checklist

1. The **offer is stated plainly early** (by section 3 on the homepage).
2. There is at least one section of **real proof / work**.
3. The page has a **clear next step** (and where appropriate a softer secondary path).
4. Section silhouettes **vary** — the page does not read as one repeated template.
5. The five-system hierarchy is respected wherever systems appear.
